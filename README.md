I'm a computer science student focused on **AI-enabled software, agent tooling, and automation**. My background includes building Discord applications and Windows utilities. I'm now working on the engineering beneath useful AI systems: structured data, tool execution, integrations, testing, and reliable behavior.

I care more about whether a system can be inspected, tested, and understood than whether it uses a fashionable model or framework.

## Current work

### Dhan AI Trader
**2026 · Private development · In progress**

A Telegram-first assistant for Indian-market research and portfolio-aware workflows, scoped around intraday and MTF use cases—not options trading.

Recent implementation work has focused on clearer portfolio classification across holdings, positions, and mutual funds, with corresponding prompt rules and tests. The project remains private and is **not a released trading product**. No trading performance or financial outcome is claimed.

### Citron AI
**2026 · Architecture exploration**

A longer-term concept for a personal AI system that can run background work while I'm away, interact with my laptop when it's available, and combine remote compute with local execution where practical.

I'm testing smaller components before committing to a server, an operating-system layer, or a larger architecture. The public [CitronAI repository](https://github.com/LemonizDev/CitronAI) does not yet contain a completed implementation, so this remains a concept—not a shipped system.

### Agent tooling and execution
**2026 · Ongoing technical investigation**

Exploring the engineering challenges behind AI coding workflows: model/provider routing, context limits, tool execution, concurrency, and local-versus-remote compute. The question that interests me is how to turn a model response into a code change that can be inspected, tested, and trusted.

This is a current area of investigation, not a claim of a standalone released tool.
